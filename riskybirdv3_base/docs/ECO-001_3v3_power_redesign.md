## 1. Context / why

riskybird v3 runs from a **1S LiPo** (4.2 V → ~3.0 V under load) and will host a **Trenz 4×5 cm FPGA SoM** (TE0712 / TE0841) that draws significant current partly off the **3.3 V** rail. The present 3v3 supply cannot meet this:

- **3v3 is generated by a buck (U11, TPS54331).** A step-down converter needs V<sub>IN</sub> comfortably above 3.3 V; it physically cannot hold 3.3 V as a 1S cell sags toward 3.3 V.
- **The buck's EN/UVLO divider is mis-set.** With R46 = 332 kΩ / R45 = 68.1 kΩ and the TPS54331 1.25 V enable threshold, turn-on is at **V<sub>IN</sub> ≈ 7.3 V** (off at ≈6.3 V). On this board V<sub>IN</sub> never exceeds ~5 V, so **the buck never enables** — today 3v3 effectively comes only from the USB LDO path (U12 → U13). There is **no working battery-powered 3v3 rail**.
- **The input path is under-rated** for the new load. At ≥3 A / 3.3 V the 1S input current is ~3.75–4 A, but the input mux **U7 (TPS2113A) is 1.25 A** and the master switch **SW3 (C&K JS102011SAQN) is 0.3 A @ 6 V**.

**Goal:** a 3.3 V rail that holds flat across the entire 1S discharge with no premature cutoff, delivers **≥3 A** (conservative; reconcile against SoM power tables later), runs from battery or USB, and is fully disconnected by SW3 with negligible standby drain.

## 2. New architecture

```
                          (charger always on the cell)
  +BATT ──┬───────────────────────────────┐
          │                                │
          │        ┌──────────────┐        │     ┌───────────────┐
  +BATT ──┴─VIN? ──┤  TPS2117 mux ├─ VOUT ─┴─────┤ P-FET hi-side │── VSYS_SW ──┐
  +5V  ────VIN? ───┤ (4A, 20mΩ)   │   (=VSYS)    │ load switch   │             │
                   └──────────────┘             └──────▲────────┘             │
                                                       │ gate                 │
  SW3 (0.3A slide) ────────────────────────────────────┘                      │
                                                                               │
                              ┌────────────────────────────────────────────────┘
                              │
                       ┌──────▼───────┐
  +5V (USB) ─►[ U4 MCP73831 ]         │  LTC3119 buck-boost  ├── +3V3 ──┬─► board + SoM 3v3 (≥3A)
              charges +BATT     VIN ──┤  (18V/5A, FB 1.2V)   │          └─►[ U10 TLV70018 ]─► +1V8
                                      └──────────────────────┘
```

- **Single +3V3 rail** from the buck-boost. The separate `+3V3_DRONE` / `+3V3_USB` nets and the output mux are eliminated.
- **SW3 = master on/off** by gating the P-FET (it carries only ~50 µA of gate-pull current, well inside 0.3 A). SW3 off → whole system unpowered, regardless of source. Residual battery draw in storage ≈ the mux's **1.32 µA** quiescent (≈ decades of shelf life; ~20× better than the old always-on TPS2113A). *Optional:* a second P-FET on `+BATT` (same gate net) drops this to ~nA if literal galvanic isolation is wanted — flagged in §6.
- **Charger (U4) stays on `+BATT` ahead of the switch**, so the cell still charges from USB with SW3 off.

## 3. Component changes

### Remove
| Ref | Part | Reason |
|---|---|---|
| U11 | TPS54331 buck | replaced by buck-boost |
| U12 | LP2985-3.0 USB LDO | single rail, no separate USB 3v3 |
| U13 | TPS2113A output mux | single rail, no output muxing |
| L3 | 6.8 µH | buck inductor → new BB inductor |
| D14 | BAT54J | buck catch diode; BB is synchronous |
| R45, R46 | 68.1 k / 332 k | mis-set buck EN/UVLO divider |
| R48, R49 | 10.2 k / 3.24 k | buck FB divider |
| C47–C50 | boot/SS/comp | buck-specific support |
| C51, C54, C55 | VCOM input caps | re-spec as BB input caps |
| U12/U13 support | their caps + U13 ILIM/status R's | identify during edit |

> **BUG FOUND — `/VSENSE` shorts two circuits.** The single `/VSENSE` net merges the buck FB divider (R48/R49 + U11.5) **and** a separate battery-monitor divider: **R51 (200 k) +BATT→node, R52 (100 k) node→GND, into ESP32 U14.12 (ADC1_CH0)**. Consequences today: the +BATT divider corrupts the buck feedback, and the ESP ADC reads the buck's 0.8 V reference instead of the cell → **battery telemetry is broken**. Likely two sense nets that accidentally share the name `/VSENSE`.
>
> **Fix in this ECO:** delete R48/R49 (old buck FB). **Keep R51/R52** but move them onto a new dedicated net `/VBAT_SENSE` that connects **only** to U14.12 — restoring ESP battery monitoring (200 k/100 k: 4.2 V→1.40 V, 3.0 V→1.00 V, fine for the ADC). The new LTC3119 gets its own clean FB divider (§4).

### Swap
| Ref | From → To | Notes |
|---|---|---|
| U7 | TPS2113A → **TPS2117** | 1.6–5.5 V, **4 A**, 20 mΩ, 1.32 µA I<sub>Q</sub>. New footprint (8-pin SOT, 2.1×1.6 mm). No ILIM pin → drop old ILIM resistor. |

**TPS2117 connections** (pinout: 1 GND, 2/7 VOUT, 3 VIN1, 4 PR1, 5 MODE, 6 VIN2, 8 ST):
- **VIN1 = +5V (USB, prioritized)**, **VIN2 = +BATT**, MODE → tie to VIN1 = **Priority mode**, PR1 per datasheet for priority.
- VOUT (2,7) = **VSYS** → P-FET source.
- ST (open-drain) → optional pull-up to +3V3 + ESP/FPGA GPIO or LED (source indicator).
- **USB-primary = load sharing:** when USB is present the system runs from USB and the cell sees only charge current (clean CC/CV termination, no simultaneous charge+discharge); when USB is removed the mux seamlessly hands off to the battery. A standalone charger (MCP73831, no power-path) requires this — battery-primary would hold the cell at 4.2 V CV and never terminate.

## 4. Key values & calculations

**Output (FB = 0.795 V typ):** V<sub>OUT</sub> = 0.795 × (1 + R<sub>top</sub>/R<sub>bot</sub>). *(Corrected — an earlier draft wrongly assumed 1.2 V.)*
→ For 3.3 V: R<sub>top</sub>/R<sub>bot</sub> ≈ 3.15 → **R<sub>top</sub> = 316 kΩ, R<sub>bot</sub> = 100 kΩ ⇒ 3.31 V** — **as built (R59/R60), confirmed correct.**

**Input UVLO / 1S cutoff (RUN pin):** sense VSYS_SW (≈ cell) with a VIN→RUN→GND divider; target rising ~3.05 V, falling ~**3.0 V** (protects the cell; holds 3.3 V flat from 4.2 V to the floor — *the cutoff fix*). ⚠️ **NOT YET BUILT:** as drawn, RUN has only a 100 kΩ pull-up (R58) to VIN and no bottom resistor → always-on, no cutoff. Add the bottom resistor, sizing with the **actual RUN threshold from the datasheet** (the earlier 1.2 V figure is unverified — same bad source as the FB error).

**Switching freq (RT):** **as built 1.5 MHz** via R62 = 48.7 kΩ; inductor **L4 = 2.2 µH** (consistent with the higher frequency). Lighter inductor than the earlier ~1 MHz suggestion — good for the drone. **PWM/SYNC:** as built tied to GND = **Burst Mode**; tie **high** for fixed-frequency PWM if clean, predictable switching noise for the sensors matters more than light-load efficiency.
**Current limit (PROG):** I<sub>PROG</sub> ≈ I<sub>SWD</sub>/25000; size R<sub>PROG</sub> for ≥3 A output (allow boost-mode inductor peak ~6–8 A).
**Bootstrap:** 0.1 µF BST1↔SW1, 0.1 µF BST2↔SW2.
**Caps:** C<sub>IN</sub> ≈ 2×22 µF + 0.1 µF; C<sub>OUT</sub> ≈ 2×47 µF (reuse existing +3V3 bulk C52/C53) + ceramics.
**Mode:** PWM/SYNC low = Burst Mode at light load (saves power when SoM idle); tie high for forced PWM if low-noise needed.
**Compensation (VC) + SS:** finalize with LTpowerCAD / datasheet for V<sub>IN</sub> 3.0–5 V, V<sub>OUT</sub> 3.3 V, 3 A.

**P-FET load switch:**
- Source = VSYS, Drain = VSYS_SW (body diode blocks when off, V<sub>IN</sub> > V<sub>OUT</sub>).
- Gate pull-up **100 kΩ** gate→source (default OFF).
- **SW3** pulls gate→GND through a series R to turn ON (carries only ~V<sub>SYS</sub>/100 k ≈ 50 µA).
- Gate→source **~47 nF** for controlled turn-on slew (limits inrush into C<sub>IN</sub>).
- *Alternative:* an integrated load-switch IC (e.g. TPS22965, 6 A, built-in slew) instead of the discrete P-FET network — fewer parts, same behavior.

## 6. Open items / decisions for review

1. ✓ **RESOLVED — USB-primary** (VIN1 = +5V). Standalone charger (no power-path) demands it: load-sharing avoids simultaneous charge+discharge / failed termination. USB-can't-supply-full-load is moot — flying is on battery; mux auto-fails-over to battery under any USB overload. (See §3.)
2. ✓ **RESOLVED — single P-FET on VSYS.** ~1.32 µA standby ≈ 1 mAh/month, ~3–10× *below* the cell's self-discharge; MCP73831 battery-pin leakage dominates the off-state floor anyway, so a second P-FET wouldn't help.
3. **3v3 current budget** is a conservative ≥3 A placeholder — reconcile against TE0712 / TE0841 power tables in the SoM workstream; may relax the regulator/inductor sizing.
4. ✓ **RESOLVED** — `/VSENSE` short diagnosed as a bug; fix folded into §3 (battery-monitor divider de-shorted onto new `/VBAT_SENSE`, restoring ESP battery telemetry).
5. ✓ **RESOLVED — LTC3119** (resistor-set output, no firmware). TPS55288 declined (I²C config).
